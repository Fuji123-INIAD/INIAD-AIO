# INIAD-AIO v1.0 Demo Guide

Date: 2026-07-08

## 目的

v1.0 は、発表で安定して見せるためのローカル学習資料デモです。

- COT101 / SEM101 / COT105 の課題候補を一覧で確認する
- MOOCs-Collect が保存したPDFを AIO 側で一覧化する
- 文字PDFではPDFのテキストレイヤーを `data/local/text_cache/` に保存する
- 画像・描画ベースPDFでは講義回、講義タイトル、PDFタイトルで検索する
- ローカル検索APIと最小UIでPDF資料を検索し、PDFを開く
- 検索結果からPDFをブラウザで開く

## Resource Index 生成

MOOCs-Collect のPDF保存先を指定して、resource index と text cache を生成します。

```powershell
.\.venv\Scripts\python.exe scripts\build_local_resource_index.py `
  --root "C:\Users\iniad\Documents\moocs-collect\2026\情報連携学概論 I" `
  --output data/local/resource_index.json `
  --extract-text `
  --text-cache-dir data/local/text_cache
```

確認すること:

- `data/local/resource_index.json` が生成される
- `resources[].text_available` が文字PDFで `true` になる
- `resources[].text_cache_path` が入る
- `data/local/text_cache/` にJSON cacheが生成される
- 画像PDFや読めないPDFは warnings に入り、処理全体は止まらない
- `summary.extracted_count` が `0` でも、講義回・講義タイトル・PDFタイトル検索は利用できる

## v1.1 experimental: MCP / Ontology / Context Card / Embedding

v1.0 発表版の安定デモはこの文書の上記手順のまま維持します。
`feature/v1.1-adventure-mcp-ontology` では、通常 Web UI を壊さない別枠の実験として以下を追加しています。

- MCP server: `python -m backend.app.mcp.aio_server --base-url http://127.0.0.1:8000`
- MCP tools: `list_tasks`, `get_task_evidence`, `list_local_resources`, `search_local_resources`, `get_local_resource`
- LocalResource ontology: `resource_kind`, `entity_type`, `source_kind`
- Context Card: `card_text` を `resource_index.json` と API response に付与
- Search mode: `/api/local/resources/search?q=...&mode=keyword|semantic|hybrid`
- Embedding fallback: 外部 API キー不要の `local-hashed-bow-v1`
- Vector cache: `python scripts/build_local_resource_vector_cache.py --index data/local/resource_index.json --output data/local/resource_vectors.json`

v1.1 実験を見る場合の最小手順:

```powershell
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
.\.venv\Scripts\python.exe -m backend.app.mcp.aio_server --base-url http://127.0.0.1:8000
```

API 確認:

```powershell
Invoke-RestMethod "http://127.0.0.1:8000/api/local/resources/search?q=security&mode=semantic&limit=5"
Invoke-RestMethod "http://127.0.0.1:8000/api/local/resources/search?q=security&mode=hybrid&limit=5"
```

注意:

- semantic は本格 embedding ではなく deterministic fallback です。
- 実データ `data/local/` と vector cache はコミットしません。
- MCP server が落ちても FastAPI / Web UI は通常どおり起動できます。

## v1.1 MCP smoke test 手順

発表前に MCP tools が実際に呼べることを確認する場合は、MCP server を直接起動する前に smoke script を使います。

1. FastAPI backend を起動:

```powershell
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

2. 別ターミナルで MCP smoke test を実行:

```powershell
.\.venv\Scripts\python.exe scripts\smoke_aio_mcp.py `
  --base-url http://127.0.0.1:8000 `
  --query "セキュリティ" `
  --mode keyword `
  --limit 5
```

成功時は `status: ok` とともに、`tools`, `task_count`, `resource_count`, `search_result_count`, `detail_checked` が JSON で表示されます。`resource_count` または `search_result_count` が 0 になる場合は、先に `data/local/resource_index.json` を生成し、実データに存在する検索語へ変更してください。

3. stdio MCP server を単体起動する場合:

```powershell
.\.venv\Scripts\python.exe -m backend.app.mcp.aio_server --base-url http://127.0.0.1:8000
```

このコマンドは stdio MCP server として標準入力を待ちます。画面が止まって見えるのは正常です。手動で止めると `Ctrl+C` による `KeyboardInterrupt` が出ますが、これは異常ではありません。

実際の MCP client から呼ぶ場合は、client 側の server command に上記 `python -m backend.app.mcp.aio_server ...` を登録し、client が `initialize`, `tools/list`, `tools/call` を送る想定です。単体起動だけでは tool call は発生しないため、発表前確認では `scripts/smoke_aio_mcp.py` を使ってください。

### できること / できないこと

- できること: pending task candidates, local resource metadata, PDF text cache, MOOCs-Collect slide text, and context snippets can be exposed through MCP.
- できないこと: AIO cannot certify deadlines or submission methods that are not present in tool results.
- PDF本文抽出0件の理由: many lecture PDFs are image/drawing-based or have no normal text layer. In that case v1.2 uses metadata or MOOCs-Collect slide text when available.
- OCR: optional fallback only. Heavy OCR dependencies are not required for the main demo.

Security-material demo:

```powershell

  --query "セキュリティ" `
  --course-title "情報連携学概論 I" `
  --lecture-key "08" `
  --mode keyword `
  --show-source-type `
  --show-provider
```

What to say:

- MOOCs-Collect `db.sqlite` stores metadata, not slide body text.
- The body text route is Google Slides SVG `aria-label` text stored in AppData `search_index`.
- AIO exposes bounded MaterialChunk snippets and labels their `source_type`/`provider`.
- If body text is not available, the demo explicitly says metadata-only and keeps the PDF/open URL path visible.

What not to say:

- Do not claim PDF text extraction is complete for all materials.
- Do not claim deadlines, submission methods, or grading details unless tool output contains them.
- Do not show or commit AppData DB/index/PDF/cookie/profile files.
