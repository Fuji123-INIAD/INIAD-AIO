調査日: 2026-06-24  
目的: 課題pageのHTML本文・構造に、期限、提出経路、本文情報が存在するか少数pageで確認する

## 調査結果の要約

今回、対象pageのHTML構造は確認できなかった。

既存の認証済み候補を使ってアクセスしたが、すべての対象pageが `https://moocs.iniad.org/signin` へリダイレクトされた。既存profileおよびstorage stateの認証は失効していると判断する。

重要:

- 以下に記載するform、button、mailto等の0件は、課題pageではなくsignin pageの観察結果である
- 課題pageに期限・form・提出リンクが存在しないという結論ではない
- 認証情報の入力、再ログイン、Cookieの出力・保存は行っていない
- HTML全文は保存していない
- 大規模同期やPlaywright巡回は行っていない

したがってPhase 3-5は、調査スクリプトの作成と認証状態の確認までは完了したが、対象HTMLの棚卸しは認証待ちで未完了である。

## 調査用スクリプト

追加したスクリプト:

```text
scripts/inspect_moocs_page_html.py
```

既定の実行:

```powershell
.\.venv\Scripts\python.exe scripts\inspect_moocs_page_html.py
```

既存storage stateを明示する場合:

```powershell
.\.venv\Scripts\python.exe scripts\inspect_moocs_page_html.py `
  --storage-state data\probe\moocs_storage_state.json
```

スクリプトは次の情報だけを標準出力へJSON表示する。

- content領域の可視テキスト長と最大1,800文字の抜粋
- 期限・提出関連キーワードの周辺文
- formのmethod、action、input type、button text
- button / submit input
- 通常リンク、外部リンク、mailtoリンク
- time要素の表示文字列とdatetime属性
- Google Slides以外のiframe URL
- signin redirectの有無

次の情報は出力・保存しない。

- Cookie
- storage stateの内容
- inputの値
- HTML全文
- ページのスクリーンショット
- ユーザー名等の認証情報

## signin pageで確認できたこと

- document title: `INIAD MOOCs`
- visible textに `Sign in with INIAD Account` が存在
- signin URL: `https://moocs.iniad.org/signin`
- 認証開始リンク: `/auth/iniad`
- content pageを示す本文・form・time要素は取得されなかった

この結果は、診断スクリプトがログイン画面をcontent pageとして成功扱いせず、`signin_redirect = true` を返せることの確認にのみ使う。

## submit channel判定

対象HTMLを取得できなかったため、今回の調査から `submit_channel` は判定できない。

実JSONにMOOCs page URLがあることだけを根拠に `submit_channel = moocs` としてはならない。現時点では次の扱いを維持する。

```text
source page: MOOCs
submit_channel: unknown
```

再認証後の調査で、次のいずれかを確認できた場合にだけ候補を更新する。

- MOOCs内formまたは提出button: `moocs`
- `mailto:` またはメール提出の明示文: `email`
- 外部formへの明示リンク: `external`
- スライドだけに提出指示がある: `slide_only`

## 再調査時に `moocs_probe.py` へ追加すべき最小フィールド候補

今回の実行では対象DOMを確認できていないため、以下は確定仕様ではなく、再認証後に検証する候補である。

### page本文

- `extracted_text`
- `content_fetched_at`
- `content_retrieval_method`

### 期限の証拠

- `deadline_text`: 原文
- `deadline_evidence_selector`: 抽出元selector
- `time_elements`: textとdatetime属性

### 提出経路の証拠

- `forms`: action、method、input type
- `buttons`: type、text
- `mailto_links`
- `external_links`: link textとURL
- `submit_instruction_text`: 提出語周辺の本文

### 教材

- `ordinary_material_links`: iframe以外の教材link
- `non_google_iframe_urls`
- `material_title`

Cookie、input value、HTML全文をprobe出力へ含めない。

## PDF / Slide本文取り込み前にHTML側で確認すべき情報

再認証後、代表pageだけで次を優先確認する。

1. 可視本文に課題内容・期限が直接書かれているか
2. `time` 要素やdata属性に機械可読な日時があるか
3. 提出formのactionとmethodがあるか
4. 提出buttonまたは回答開始buttonがあるか
5. mailto、外部form、別pageへの提出linkがあるか
6. 課題本文がHTMLではなくGoogle Slidesだけにあるか
7. 課題解説pageに自己採点や結果提出の指示があるか

HTML側に十分な情報があるなら、PDF / Slide本文取り込みより先に軽量なHTML本文抽出を接続できる。HTML側に情報がなく、Slides内にしか存在しない場合は、PDF / Slide ingestを期限・課題情報源として扱う必要がある。
