# INIAD-AIO v0.3 MOOCs HTML Source Inventory

調査日: 2026-06-24  
目的: 課題pageのHTML本文・構造に、期限、提出経路、本文情報が存在するか少数pageで確認する

## 結論

再認証後、代表4pageすべてを `signin_redirect = false` で取得できた。MOOCsの課題page HTMLには、task titleとURLだけでなく、次の情報が含まれている。

- 課題・回答に関する可視本文
- 提出指示
- 明示期限または相対期限
- 「問題を開く」「提出」等の操作button
- Quizの座席番号入力や回答UI
- 課題解説に埋め込まれたGoogle Drive preview iframe

したがって、PDF / Slide本文取り込みへ進む前に、MOOCs page HTMLから軽量な本文・期限・提出UIの証拠を取得する価値が高い。`deadline_text`, `submit_channel`, `accepting_status` を推定するための一次情報として利用できる可能性が高い。

ただし、今回の調査では期限抽出や提出経路判定を本実装しない。HTML全文、Cookie、input値、スクリーンショットを保存しない方針も維持する。

## 調査方法

調査スクリプト:

```text
scripts/inspect_moocs_page_html.py
```

実行コマンド:

```powershell
.\.venv\Scripts\python.exe scripts\inspect_moocs_page_html.py
```

認証済みの `data/probe/moocs_profile` をpersistent contextとして使用した。再認証前に発生していたsignin redirectは解消済みである。

スクリプトは次の情報だけを標準出力へ表示する。

- content領域の可視テキスト抜粋
- 期限・提出関連キーワードの周辺文
- form、button、submit input
- 通常リンク、外部リンク、mailtoリンク
- time要素
- Google Slides以外のiframe URL
- signin redirectの有無

次の情報は出力・保存しない。

- Cookieおよびstorage stateの内容
- inputの入力値
- HTML全文
- スクリーンショット
- ユーザー名等の認証情報

## page別の観察結果

### COT101 通常課題: 課題1-1-1

- MOOCs本文を取得できた
- 本文中に提出指示が存在した
- 提出操作に関係するbuttonが存在した
- form要素は0件だった
- time要素、mailtoリンク、外部提出リンクは確認できなかった
- HTML本文とbuttonが `submit_channel = moocs` の根拠候補になる

このpageでは、task titleやURLだけでなく、可視本文とbuttonを取得することで「MOOCs上で実施・提出する課題」である可能性をより強く判定できる。

### COT101 課題解説

- MOOCs本文を取得できた
- 「次の講義前日まで」という相対期限が存在した
- 提出buttonが存在した
- form要素は0件だった
- Google Drive preview iframeが存在した
- time要素、mailtoリンク、外部提出リンクは確認できなかった

「次の講義前日まで」は人ごとの講義曜日や例外日程に依存するため、確定した `deadline_at` へ直接変換しない。まず次のような証拠として保持するのが安全である。

```text
deadline_text: 次の講義前日まで
deadline_source: moocs
deadline kind: relative
```

課題解説pageにも提出buttonがあるため、単なる閲覧資料ではなく、自己採点結果等のaction itemを含む可能性が高い。`review_or_feedback` を除外せず別枠に保持する現方針と整合する。

Google Drive preview iframeは既存のGoogle Slides検出だけでは拾えない可能性があるため、`non_google_iframe_urls` の取得が有用である。

### COT105 Report: レポート課題

- MOOCs本文を取得できた
- 「4月21日火曜日23時59分」という明示期限が存在した
- 提出buttonが存在した
- form要素は0件だった
- time要素、mailtoリンク、外部提出リンクは確認できなかった

可視本文から `deadline_text` を取得できる可能性が高い。一方、原文に年度やtimezoneが明記されていない場合、正規化時にcourse年度とAsia/Tokyoを補う規則が必要になる。今回の段階では原文を保存し、`deadline_at` への変換は後続設計で扱う。

提出buttonとMOOCs本文中の提出指示は `submit_channel = moocs` の強い根拠候補になる。

### COT105 Quiz: Part1 Quiz

- MOOCs本文を取得できた
- 座席番号入力欄が存在した
- 回答UIが存在した
- 提出buttonが存在した
- form要素は0件だった
- time要素、mailtoリンク、外部提出リンクは確認できなかった

標準のHTML `form` がなくても、JavaScriptによる回答・提出UIが構成されている。このため、submit channel判定を `form` の有無だけに依存させてはならない。

座席番号等のinput値は個人情報になり得るため、値を保存しない。将来probeへ入力要素情報を追加する場合も、type、name、label等の構造だけを扱い、valueは取得・保存しない。

## deadline抽出への示唆

今回、HTML本文で2種類の期限表現を確認した。

### 明示期限

例:

```text
4月21日火曜日23時59分
```

候補となる処理:

1. 原文を `deadline_text` として保持
2. course年度を補完
3. timezoneをAsia/Tokyoとして解釈
4. 曜日と日付の整合性を検証
5. 安全に解釈できた場合だけ `deadline_at` を設定

### 相対期限

例:

```text
次の講義前日まで
```

相対期限は、講義曜日、クラス、休講、例外日程に依存する。確定値として `deadline_at` に入れず、当面は次の情報として保持する。

- `deadline_text`
- `deadline_source = moocs`
- `deadline_note`
- 将来の `estimated_deadline_at`

## submit channel判定への示唆

今回の4pageでは、mailtoや外部提出linkは確認されず、MOOCs本文中の提出指示と提出buttonが確認された。この組み合わせは `submit_channel = moocs` の根拠として利用できる可能性が高い。

判定候補:

```text
MOOCs本文に提出指示がある
AND MOOCs page内に提出buttonまたは回答UIがある
AND mailto / 外部提出linkがない
=> submit_channel = moocs の高確度候補
```

ただし、button textだけで確定せず、周辺本文、link、buttonの操作先、accepting statusを合わせて判断する。

## accepting statusへの示唆

課題pageの可視本文やbutton状態から、受付中・受付終了・未開始等を判断できる可能性がある。

今後確認・抽出する候補:

- 「受付中」「受付終了」「提出済み」「未提出」等の本文
- 提出buttonの有無
- buttonのdisabled属性
- 「問題を開く」等の開始button
- 回答UIが表示されているか

まず原文を `accepting_status_text` として保持し、状態値への正規化は実例を増やしてから行う。

## `moocs_probe.py` に追加する最小フィールド候補

### 本文・期限

- `extracted_text`: navigation等を除いた可視本文
- `keyword_contexts` または `deadline_instruction_text`: 期限・提出語の周辺文
- `deadline_text`: 期限表現の原文
- `accepting_status_text`: 受付状態を示す原文

### 操作要素

- `buttons`: text、type、disabled等。input valueは含めない
- `submit_button_present`: 提出buttonの有無
- `ordinary_links`: link textとURL
- `external_links`: 外部hostへのlink textとURL
- `mailto_links`: mailto URL。本文や宛先の保存範囲は別途検討する
- `time_elements`: textとdatetime属性

### iframe・教材

- `non_google_iframe_urls`: Google Slides以外のiframe URL
- Google Drive preview iframeを識別できるmaterial type

### 取得情報

- `content_fetched_at`
- `content_retrieval_method`
- `signin_redirect`

Cookie、storage state、input値、HTML全文、スクリーンショットはprobe出力へ含めない。

## PDF / Slide本文取り込み前にHTML側で取るべき情報

今回の結果から、次の情報はPDF / Slide ingestより先にHTML側で取得する価値がある。

1. 課題説明を含む可視本文
2. 明示期限・相対期限の原文
3. 提出指示の周辺文
4. 提出・問題開始buttonの有無と状態
5. 受付状態を示す本文
6. mailtoおよび外部提出link
7. 通常教材link
8. Google Slides以外のiframe URL

COT101課題解説のGoogle Drive previewのように、action itemの説明や教材がiframe側にある場合は、HTML本文取得とSlide/PDF ingestを相互補完させる。

## 次の実装単位案

次は大規模同期ではなく、`moocs_probe.py` のpage取得結果へ最小限のHTML証拠フィールドを追加する小さなPoCが適切である。

推奨順序:

1. `extracted_text` とkeyword周辺文
2. `buttons` と `submit_button_present`
3. `ordinary_links`, `external_links`, `mailto_links`
4. `time_elements`
5. `non_google_iframe_urls`
6. `deadline_text`, `accepting_status_text` の候補抽出

抽出した原文を確認してから、`deadline_at` と `submit_channel` の正規化規則を別Phaseで実装する。DBスキーマやimporterは、取得フィールドと実例が安定するまで変更しない。
