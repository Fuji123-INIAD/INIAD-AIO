# INIAD-AIO v0.3 Deadline / Submit Channel Source Inventory

調査日: 2026-06-24  
対象データ: `data/probe/moocs_course_details.json`  
目的: v0.3の期限・提出経路取得を実装する前に、既存の実MOOCs詳細JSONに残っている情報を確認する

## 結論

現在の `moocs_course_details.json` には、課題期限や提出経路を確定できる情報は残っていない。

- `due`, `deadline`, `close`, `closing`, `締切`, `期限`, `提出期限` に相当するキーはない
- page本文、説明、HTML、フォーム、ボタン、リンクテキストも保存されていない
- 日時として保存されているのはcourse単位の `fetched_at` だけである
- task候補にはMOOCsのpage URLがあるが、そのページが提出画面であることまでは分からない
- materialはGoogle Slides iframeのURLと種別だけで、スライド本文はない

一方、`moocs_probe.py` は対象ページを実際に開いているものの、詳細JSONへ保存するのはタイトル、URL、Google Slides iframeだけである。したがって、今回のJSONから「元のMOOCsページにも期限が存在しない」とは判断できない。期限や提出方法がHTML本文、フォーム、リンク、またはスライド内に存在し、probeが保持していない可能性がある。

## 3. 期限らしい文字列の調査

キー名と文字列値について、次の語を検索した。

```text
due, deadline, close, closing, end,
締切, 期限, 提出期限, 提出,
submit, submission, email, メール
```

課題期限・提出方法として利用できる一致は0件だった。

見つかった見かけ上の一致は、Google Slides URLの `pubembed` 等に含まれる英字部分であり、期限を表す `end` ではない。また、「表とフォーム」というpage titleの「フォーム」も、提出フォームを示す証拠ではない。

日付・時刻らしい文字列も調べたが、実際の日時はcourseの `fetched_at` だけだった。「これまでの復習」に含まれる「まで」など、期限とは無関係な一致を除くと、pageやmaterial周辺に期限候補はない。

## 5. URLから `submit_channel` を推定できるか

JSON内のURL hostは次の2種類だった。

| host | URL数 | 主な用途 |
|---|---:|---|
| `moocs.iniad.org` | 394 | course 2、lesson 45、page 347 |
| `docs.google.com` | 237 | Google Slides material |

すべてのtask候補はMOOCs上のpage URLを持つ。ただし、これは「MOOCsに掲載されたページ」であることを示すだけで、「MOOCs上で提出する」ことを保証しない。

例えば、MOOCs pageに次の内容が書かれている可能性がある。

- MOOCs上のフォームから提出する
- メールで提出する
- スライド記載の方法に従う
- 外部サービスへ移動する
- 課題説明だけで、提出操作は別の場所にある

そのため、page URLのhostだけを根拠に `submit_channel = moocs` と確定するのは避ける。

現時点で設定するなら、次の区別が必要である。

- `source_page_host = moocs.iniad.org`: 情報掲載元として確定可能
- `submit_channel = unknown`: 提出UIまたは明示文を確認できない場合
- `submit_channel = moocs`: MOOCs内の提出フォーム、提出ボタン、明示的な提出指示を取得できた場合だけ

URL pathの `report`, `quiz`, `exercise` はtask判定の補助にはなるが、提出経路の確定根拠としては弱い。

## 6. `moocs_probe.py` が現在取得しているもの

`backend/moocs_probe.py` の出力モデルは次の構造で固定されている。

- `CourseDetailProbeRecord`: course title、URL、lessons、取得時刻
- `CourseLessonProbeRecord`: lesson title、URL、pages
- `CoursePageProbeRecord`: page title、URL、materials
- `CourseMaterialProbeRecord`: material type、URL、取得方法

`probe_course_details()` は各lesson pageへ遷移した後、次の処理だけを行う。

1. `extract_content_page_title()` でpage titleを取得
2. `extract_google_slides_materials()` でGoogle Slides iframeを取得
3. title、URL、materialsを `CoursePageProbeRecord` に保存

本文、表、フォーム、ボタン、通常リンク、`time` 要素、data属性は詳細JSONへ保存していない。

このため、現状は次のどちらかを区別できない。

1. 元のMOOCs HTMLに期限・提出情報が存在しない
2. 元のHTMLには存在するが、probeが抽出・保存していない

現在の実装とJSON構造からは、2の可能性を十分に残す。

## 7. 期限がHTML本文側にしかない可能性

可能性はある。特に次の場所が候補になる。

- page本文中の文章
- 見出し、箇条書き、表
- `time[datetime]` 等の時刻要素
- 提出フォーム周辺のラベル
- submitボタン付近の説明
- 通常リンクのテキストと遷移先
- HTMLのdata属性や埋め込みJSON
- Google Slides内の本文

ただし、今回の調査ではHTMLスナップショットを読んでおらず、MOOCsへもアクセスしていないため、実際にどこへ存在するかは未確認である。

また、期限がページ本文にもなく、「通常は次回授業前日まで」のような授業規則や口頭説明だけで決まる場合もある。その場合は明示期限ではなく、Phase 3-1.7で整理した推定期限として扱う必要がある。

## 8. 今後追加取得を検討するフィールド

### page本文

- `extracted_text`: ナビゲーション等を除いた可視本文
- `content_fetched_at`: 本文取得時刻
- `content_retrieval_method`: HTTP / Playwright / DOM selector等
- `content_hash`: 内容変更検知用

全文HTMLを恒久保存する場合は、サイズと認証情報・個人情報混入の確認が必要である。まずは必要箇所を抽出した本文と根拠断片を保存する方が安全である。

### 期限の根拠

- `deadline_text`: 「提出期限: 6月30日 23:59」等の原文
- `deadline_at`: 明示文を安全に正規化できた場合の確定値
- `deadline_source`: `moocs`, `slide`, `rule_estimated`, `unknown`
- `deadline_evidence`: 抽出元selector、周辺文、source URL
- `timezone`: 明示がなければAsia/Tokyoとするかの規則

不完全な日付、年度省略、曜日だけの表現は、確定値へ変換せず原文と推定候補を分ける。

### 提出経路の根拠

- `submit_channel`: `moocs`, `email`, `slide_only`, `external`, `unknown`
- `submission_url`: 実際の提出先URL
- `form_action`, `form_method`: MOOCs内フォームがある場合
- `button_text`: 提出・回答開始等の操作ラベル
- `mailto_url`: メール提出指示がある場合
- `external_links`: 外部フォーム・サービスへのリンク
- `submit_instruction_text`: 提出方法を示す本文断片

### page種別・構造

- `page_kind`: assignment / quiz / report / review / content等
- `links`: link text、href、rel
- `forms`: action、method、入力欄名、ラベル
- `time_elements`: 表示文字列とdatetime属性
- `structured_data`: 埋め込みJSON等に期限がある場合

### material

- `material_title`
- `material_text` または後続PDF/Slides ingestへの参照
- `material_fetched_at`
- `material_content_type`
