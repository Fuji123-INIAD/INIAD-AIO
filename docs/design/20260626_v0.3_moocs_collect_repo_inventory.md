作成日: 2026-06-26

目的: AIO 側で PDF / Google Slides / text / index 連携を自作する前に、MOOCs-Collect で既に使える仕組みを把握する。

## 1. 調査目的

Phase 3-5 から Phase 3-8.5 で、AIO は MOOCs page HTML から課題本文、提出UI、期限候補、受付状態候補を取得し、`tasks.raw_json._aio_task_meta` に保存できるようになった。

一方で、課題内容・期限・提出方法は、MOOCs HTML ではなく PDF や Google Slides 側にだけ書かれている可能性がある。そこで、AIO 側で PDF / Slides 本文抽出を実装する前に、MOOCs-Collect が既に持っている取得・保存・検索の仕組みを調査する。

今回は調査メモのみを追加する。MOOCs-Collect 本体、AIO コード、DB スキーマ、importer、`backend/main.py` は変更しない。

## 2. MOOCs-Collect を先に調査する理由

MOOCs-Collect は、INIAD MOOCs のスライド取得・PDF保存・全文検索を目的にした既存ツールである。README でも次の機能が明記されている。

- スライド一括ダウンロード
- PDF出力
- デスクトップアプリでの全文検索
- CLI版
- PDF結合ユーティリティ `mcmerge`

AIO が同じ Google Slides / PDF / text extraction を最初から再実装すると、認証、Google Slides HTML解析、SVG処理、PDF生成、検索index作成を重複して持つことになる。まずは MOOCs-Collect の成果物を read-only で参照できるかを検討するのが安全。

## 4. Slides / PDF / text / index の流れ

### Google Slides 取得

`src/repository/slide.rs` の流れ:

1. MOOCs page URL を組み立てて HTML を取得する
2. `iframe` を走査する
3. `https://docs.google.com/.../presentation/d/.../(embed|pubembed)?` に一致する iframe を `Slide` として扱う
4. Slide embed URL を取得する
5. embed HTML 中の escaped SVG を regex で抽出する
6. unicode escape を decode する
7. `ProcessedSvg` として `SlideContent` にまとめる

この段階では raw SVG はメモリ上の `SlideContent` として扱われる。コード上、raw SVG を永続保存する仕組みは見つからなかった。

### text 抽出

`src/domain/models/slide.rs` の `ProcessedSvg.get_texts()` が、SVG内の次のような要素から `aria-label` を取り出す。

```text
g role="img" aria-label="..."
```

`SlideContent.get_texts()` は、各 SVG の text を slide 単位でまとめる。

この text は2箇所で使われる。

- PDF生成時の透明 text layer 埋め込み
- desktop版 Tantivy index への登録

### PDF生成

`src/pdf/mod.rs` の流れ:

1. `PreProcessor` が SVG内の外部画像を fetch して base64 data URI に埋め込む
2. `g[role=img][aria-label]` の内容を透明な `<text>` として SVG に埋め込む
3. `svg2pdf` で SVG を PDF 化する
4. `lopdf` で複数ページを merge する

つまり、MOOCs-Collect が作るPDFには、aria-label 由来の text layer が入る可能性がある。AIO側でPDF text layer抽出をする場合、MOOCs-Collect生成PDFは比較的扱いやすい可能性がある。

### PDF保存

Desktop版:

- default downloadDir: Documents 配下の `moocs-collect`
- 保存構造: `{downloadDir}/{year}/{course_name}/{lecture_name}/{page_title}.pdf`
- 複数slide iframeがある場合: `{page_title} (n).pdf`

CLI版:

- 保存構造: `{path}/{course_name}/{lecture_group} - {lecture_name}/{page_slug} - {page_title}.pdf`
- 複数slide iframeがある場合: `{page_slug} - {page_title} (n).pdf`

`mcmerge` はこの2形式を parse できる。

### SQLite metadata

Desktop版は app data directory 配下の `db.sqlite` に次のテーブルを持つ。

- `courses`
  - `year`, `slug`, `name`, `sort_index`
- `lectures`
  - `course_id`, `slug`, `name`, `sort_index`
- `pages`
  - `lecture_id`, `slug`, `name`, `sort_index`, `key`
- `slides`
  - `page_id`, `idx`, `url`, `pdf_path`, `downloaded_at`

`pages.key` は `year/course_slug/lecture_slug/page_slug` 形式の composite key。AIO の `page_url` からも同等の key を作れるため、対応付けに使いやすい。

### 全文検索 index

Desktop版は Tantivy を使う。

index path:

- app data directory 配下の `search_index`

schema:

- `key`
- `facet`
- `content`
- `content_ja`
- `content_bi`

`content_ja` は Lindera / UniDic 系の日本語 tokenizer、`content_bi` は bigram tokenizer。検索結果は `SearchResult` として次を返す。

- `page_key`
- `facet`
- `content_snippet`
- `highlighted_content`
- `score`

ただし、この index は Tantivy の内部形式であり、AIO Python backend から直接読むには Rust/Tantivy連携か別プロセスが必要になる。短期では、AIOが直接 index を読むより、PDF text layer または SQLite `pdf_path` を読む方が扱いやすい。

## 5. AIO から利用できそうな成果物

### 有望

#### Desktop `db.sqlite`

read-only 参照候補。

使える情報:

- course year / slug / name
- lecture slug / name
- page slug / name / key
- slide idx
- Google Slides URL
- local PDF path
- downloaded_at

AIOの `moocs_probe.py` / importer が持つ `page_url` から `year/course/lecture/page` を抜き出せば、`pages.key` と対応付けられる。

#### Desktop PDF保存先

read-only 参照候補。

使える情報:

- PDFファイル本体
- PDF path
- course / lecture / page のディレクトリ構造

ただし、実講義本文・PDF本体は AIO repo にコピーしない。

#### Generated PDF text layer

MOOCs-Collect は SVG aria-label を透明 text としてPDFに埋め込む。AIO側では、MOOCs-Collect生成PDFに対して text layer 抽出PoCを試す価値が高い。

#### `pages.key`

AIO側の `page_url` と対応付けしやすい。

例:

```text
https://moocs.iniad.org/courses/2026/COT105/00/exercise
=> 2026/COT105/00/exercise
```

### 条件付きで有望

#### Tantivy `search_index`

既に slide text が index 済みなら、期限や提出語を検索できる可能性がある。

ただし:

- Pythonから直接読むのは重い
- Tantivy schema / analyzer と密結合
- index format の互換性に注意
- index 内に実講義本文が入るため、AIO repo へコピー不可

短期では直接利用を避け、必要なら将来 Rust小ツールまたは MOOCs-Collect 側APIで read-only 検索する。

#### PDF path fallback

desktop DBがない場合、`mcmerge` の path parse と同様にPDFパス規則から metadata を推定できる。ただし、ファイル名変更や保存形式差分に弱いため、DBがある場合はDB優先。

## 6. AIO から利用する場合の統合方針

### 原則

- MOOCs-Collect は downloader / extractor として扱う
- AIO は read-only で参照する
- MOOCs-Collect の DB、PDF、cache、index をAIO側から書き換えない
- 実講義本文、PDF、Slide画像、SVG、indexをAIO repoにコピーしない
- AIOの `tasks.raw_json._aio_task_meta` には短い証拠だけを保存する

### AIO task meta に保存してよい候補

- `deadline_text_candidates`
- `deadline_source_candidate`
- `material_source_candidate`
- `material_url`
- `moocs_collect_page_key`
- `moocs_collect_slide_idx`
- `moocs_collect_pdf_path` は保存する場合でも local private path なので慎重に扱う
- `evidence_snippet`
- `content_retrieval_method`
- `content_fetched_at`

保存しないもの:

- PDF本文全文
- Slide本文全文
- raw SVG
- Slide画像
- cache
- Tantivy index内容
- Cookie / storage_state / token / password

### 短期の統合案

1. AIO設定に MOOCs-Collect desktop DB path と downloadDir を指定できるようにする
2. AIOが `db.sqlite` を read-only で開く
3. AIO page URL から `pages.key` を作る
4. `pages -> slides` を引いて `url`, `pdf_path`, `idx` を取得する
5. `pdf_path` が存在する場合だけPDF text layer抽出PoCを実行する
6. 抽出したtextから期限・提出語周辺の短い snippet だけを task meta に入れる

## 7. 利用できない場合の代替案

### AIO側 PDF text layer抽出PoC

MOOCs-Collect生成PDFに透明 text layer が入る可能性が高いため、まずPDF text抽出を試す。

候補:

- `pypdf`
- `pdfplumber`
- Poppler `pdftotext`

対象は少数PDFのみ。全文や実PDFをGitに入れない。

### Google Slides export / preview / SVG解析PoC

PDFが存在しない場合、AIO側でGoogle Slides URLから取得するPoCを検討する。

候補:

- MOOCs page iframe URLを利用
- Google Slides embed HTMLからSVG抽出
- SVG `aria-label` の短い周辺文だけ抽出

ただし、認証・アクセス権・Google側仕様変更の影響を受けやすい。MOOCs-Collect の既存実装を参考にする。

### OCR

OCRは最後の手段。

理由:

- 重い
- 誤認識が多い
- 画像保存・処理の取り扱いが難しい
- 著作権・個人利用範囲の注意が増える

## 8. セキュリティ・著作権上の注意

- 実講義本文を docs / fixture に貼らない
- PDFをGitに入れない
- Slide画像をGitに入れない
- raw SVGをGitに入れない
- cacheをGitに入れない
- Tantivy indexをGitに入れない
- `db.sqlite` をGitに入れない
- `store.json` をGitに入れない
- cookie / storage_state / token / password / keyring内容を読まない
- 認証情報を標準出力に表示しない
- 認証情報をAIO側に保存しない

MOOCs-Collect の `login` command は keyring に password を保存し得る。AIOは keyring を読まない。
